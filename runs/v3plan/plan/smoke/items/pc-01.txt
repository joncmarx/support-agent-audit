Title: Node to consolidate incoming text messages into a single batch

In a typical WhatsApp conversation, we often receive 2–3 messages in a row that are all part of the same context. Instead of sending each line individually in the Gmail output, I’d like to group them together into a single, consolidated message before sending

Does anyone have advice on which node I should use for this? Ideally, the node would be able to wait for about 90 seconds, store incoming messages during that time, and then combine them into one context before passing them to the next node

## The reference packet
Accepted answer from the forum (it solved the problem for the asker):
<<<
@Maxwell45 This is the classic debounce pattern, and there’s no single built-in node that does it, you need a small combo:

Trigger fires on each incoming message → write it to storage Redis, a Data Table, or even Airtable keyed by the sender’s phone number, appending to a running buffer rather than overwriting.

Wait node set to 90 seconds.

After the wait, check a timestamp, if the buffer’s “last updated” time is still within the last ~5 seconds of when this particular execution started waiting, it means no newer message has come in, so this execution is the “last” one and should proceed. If a newer message arrived during the wait, this execution should just stop (another execution will pick up the final flush).

If proceeding: read the full buffer, join the messages into one string, clear the buffer, and pass it downstream to Gmail.

The reason it’s not simpler: every incoming WhatsApp message triggers its own separate execution in n8n (there’s no native “hold and merge” trigger), so you need external state (Redis is ideal, fast, and has a natural TTL for buffer expiry) to coordinate across those parallel executions and make sure only the last one actually sends.
>>>

Reference note — key step of the fix, as recorded by the labeler: Build a debounce: append each incoming message to external storage (Redis or a Data Table) keyed by sender, use a Wait node for 90 seconds, let only the execution that sees no newer message proceed, then join the buffer into one string, clear it, and send it via Gmail.

## Send more than 30 messages per second

The Telegram API has a [limitation](https://core.telegram.org/bots/faq#broadcasting-to-users) of sending only 30 messages per second. Follow these steps to send more than 30 messages:

1. **Loop Over Items node**: Use the [Loop Over Items](../../core-nodes/n8n-nodes-base.splitinbatches.md) node to get at most 30 chat IDs from your database.
2. **Telegram node**: Connect the Telegram node with the Loop Over Items node. Use the **Expression Editor** to select the Chat IDs from the Loop Over Items node.
3. **Code node**: Connect the [Code](../../core-nodes/n8n-nodes-base.code/README.md) node with the Telegram node. Use the Code node to wait for a few seconds before fetching the next batch of chat IDs. Connect this node with the Loop Over Items node.

You can also use this [workflow](https://n8n.io/workflows/772).

## Using loops in n8n

n8n nodes take any number of items as input, process these items, and output the results. You can think of each item as a single data point, or a single row in the output table of a node.

![The Customer Datastore node output](../.gitbook/assets/customer_datastore_node.png)

Nodes usually run once for each item. For example, if you wanted to send the name and notes of the customers in the Customer Datastore node as a message on Slack, you would:

1. Connect the Slack node to the Customer Datastore node.
2. Configure the parameters.
3. Execute the node.

You would receive five messages: one for each item.

This is how you can process multiple items without having to explicitly connect nodes in a loop.

1. Select the nodes you want to group. Drag a selection box around them, or hold `Ctrl/Cmd` and click each node.
2. Select the **Group nodes** icon  in the toolbar above the selection, select **Group nodes** in the selection's right-click menu, or press `Ctrl/Cmd` + `G`.

## The reply (plain text)
<<<
You can do this with standard flow logic: collect the incoming items, wait, then combine them in a Code node before the next step.

1. Use a trigger or input node to receive each message.
   n8n processes items one by one by default, so each incoming text is usually a separate item [2].

2. Add a `Wait` step if you want a 90-second window.
   A wait is the right general mechanism for “hold messages for a bit, then continue.” If your messages arrive as separate workflow executions, you’ll also need some way to store them temporarily between runs (for example, in a database or sheet). n8n itself does not have a dedicated “buffer incoming messages for 90 seconds” node in the docs I have.

3. Use a `Code` node to merge the text fields into one message.
   In the Code node, combine the incoming items into a single string, for example by joining each item’s text field with line breaks. This is general JavaScript:
   ```js
   const combined = items.map(item => item.json.text).join('\n');
   return [{ json: { combined } }];
   ```

4. Send the combined output to your Gmail node.
   If you’re using Gmail, feed the single combined field into the message body. The Gmail node supports normal message retrieval/filtering, but batching/combining is done upstream in your workflow [3][7].

If your use case is actually sending Telegram messages in bursts, n8n’s docs suggest `Loop Over Items` plus a `Code` node to pause between batches [1], but for “combine 2–3 incoming WhatsApp lines into one context,” the key piece is the Code node plus a place to store messages until the window closes.
